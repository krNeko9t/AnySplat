## Question

`physgm_dpt` 训练时的实例成员是 **GT instance mask 圈的像素**；
推理时是 **HDBSCAN 在高斯上聚出来的高斯集合**。这条差异不可能消除，只能量。

**做法**：在 `3dovs/bench` 上，用**同一份 `gau_phys_feat`、同一个训练好的 MLP**，
只换成员集合，比两组 (E, ν, ρ)：

- **甲**：GT mask 反投影到高斯 → 该集合上 `num_ray` 加权平均 → MLP → denormalize；
- **乙**：HDBSCAN 实例的高斯集合 → 同样的平均 → 同一个 MLP → denormalize。

⚠️ 甲乙的实例**不是一一对应的**（HDBSCAN 会把一个 GT 物体切开、也会把几个并起来）。
先定一条配对规则（建议：高斯集合的 IoU 最大者配对，并报未配上的两侧数量），
配对规则本身要写进 Answer——不同的配对规则会给出不同的差值。

## 一并要报的

- **噪声底**：同一条路跑两遍的差（地图 F4：`atomicAdd`，maxabs 3.4e-3 / 相对 1.7e-6）。
  差值不显著高于噪声底就不算差异。⚠️ 不许用 `torch.equal`。
- **`mu_spread`**（01 号票 (d) 条的定义）：每个高斯单独过一遍同一个 MLP 得到的 `mu` 的标准差。
  甲乙两侧都报——若乙的 `mu_spread` 明显大于甲，说明 HDBSCAN 把不同材质的东西聚进了一个实例，
  这比 (E,ν,ρ) 的均值差更能说明问题。
- **头输出的 `var`** 与 `mu_spread` **分开摆**，别合成一个数。

## 完成判据

一张表：每个配上的实例一行，甲的 (E,ν,ρ)、乙的 (E,ν,ρ)、相对差、两侧的 `var` 与 `mu_spread`；
加上噪声底、配对规则、未配上的实例数。

一句话结论：**成员集合这处不等价，在本图的判据（「有个值就行」）下是可忽略的，还是不可忽略的。**
若不可忽略，写清楚它会怎么影响后续（那是下一张图的事，不是本图的）。

## ⚠️ 03 号票推翻了本票的前提（2026-09-09），方法要改

本票原来的甲侧是「GT mask 反投影到高斯」。**03 号票实测：`sam/mask` 的 id 不是跨视角一致的**
——帧 00 是 id 1–8、帧 12 是 1–7、帧 24 是 1–9，**同一个 id 在不同帧指不同物体**。
它是逐帧 SAM 输出，**根本不是 3D 实例 GT**。

⇒ **04 号票报的「bench GT 是 10 个实例」也不成立**（那是 36 帧上 id 的并集最大值，
与老图记的「8」是同一类错误——那是帧 00 的计数）。
⇒ **04 的池化口径读数仍然有效**：它两侧用的是同一套 id 语义，比的是「2D 池 vs 3D 池」
这个协议差，污染两侧对称抵消。**但它不能被当成实例级的物性结论。**

### 改后的做法

**第一步：先造一套真正的 3D GT 实例，或者证明造不出来。**
逐帧、逐 id 单独 trace 到高斯（04 的 one-hot + 常数覆盖平面那套现成），
得到每个 (帧, id) 的高斯集合，再把**高斯集合重叠度高的跨帧 id 连成同一个 3D 实例**
（连通分量，阈值写进 Answer）。这本来就是 trace 白送的能力。

**若连接结果是歧义的**（一个 3D 实例被链到互相矛盾的帧 id、或链出的实例数不稳定），
**那就是本票的答案**：`3dovs/bench` 上不存在可用的 3D 实例 GT。
这个结论本身很有价值——它一次性判掉一整类未来的指标（任何拿 `sam/mask` 当 3D GT 的 IoU / mIoU），
**如实写出来即可，不要硬凑一个数**。

**第二步（只有第一步成功才做）**：用连好的 3D GT 实例集合作为甲，HDBSCAN 实例作为乙，
按原方案比两组 (E, ν, ρ)。配对规则仍要写进 Answer。

### 03 号票交下来的其它前提

- **噪声底是「零标签变动」**：两次独立 trace 得到的 9 个实例完全相同（ARI 1.0000）。
  所以本票任何标签差异都是真的。
- **bench 的 HDBSCAN 实例是 9 个**：2 个 stuff（墙 555,810 高斯、地板 366,893）+
  6 个真物体（猫 27,402 / 娃娃 18,876 / 葡萄 13,434 / 叶 7,840 / 车 7,581 / 蛋挞 6,847）+
  1 个 1,025 高斯的碎片。**乙侧不用重跑聚类**，直接用 03 的标签。
- **bench GT 是 84.2% stuff 像素**（不是地图写的 62%）⇒ 甲侧能配上的物体实例本来就少。
