## Question

论文在 **2×A800 80G** 上跑；我们是 **8×A100 40G**，单卡显存**只有一半**，而且要 backbone
全量微调（不是原来的 `freeze_backbone: true`）。在写配置（T7）之前必须知道每卡能放多少。

算清楚单卡峰值显存，输入条件：

- VGGT 24 层 alternating attention + DINOv2 backbone，**全部参数可训**（AdamW → 参数 + 梯度 +
  两份动量 ≈ 参数量 × 16 bytes，bf16-mixed 下还要算 fp32 master weights）
- 1 场景 × 最多 8 视角 × 448×448
- GS head + PartHead 的 DPT 激活
- `voxelize: true, voxel_size: 0.002` 之后的高斯数量（**这个要估**：448×448×8 = 1.6M 像素级
  高斯，体素化后剩多少？看 `voxelizaton_with_fusion` 的实现）
- **两路** gsplat 渲染：RGB(SH deg 4) + 8 维实例特征，各 8 个视角

要回答：

1. 参数/优化器状态占多少（把 `src/model/arch/anysplat.py` 的实际模块过一遍数参数量，
   本机没 python 环境，按 VGGT-1B + DPT head 的公开数字估算即可）
2. 激活占多少，8 视角是否必须开 gradient checkpointing
3. 结论：**每卡 1 场景 × 8 视角 @448 在 40G 上可行吗**？如果不行，最先该砍哪个
   （视角数上限 → 6？分辨率 → 384？梯度检查点？）
4. 顺带给出每步耗时的量级估计，用来校准「10k steps 要跑多久」

**产出**：一张显存分项表 + 一个明确的「每卡配置」建议 + 需要打开的省显存开关清单。

## 解决

**结论：每卡 1 场景 × 8 视角 @448 在 40G 上可行（估算峰值 ~28–32GB），但有一个致命前提：
把采样器的 `max_img_per_gpu` 从 24 降到 8。** 现状 24 会让 `DynamicBatchSampler`
（`src/dataset/data_sampler.py:206-210`，每卡 batch = ⌊24/每场景图像数⌋）往一张卡塞
**3 个 8 视角场景**，激活 ×3，必 OOM。

### 显存分项表（每卡，bf16-mixed，backbone 全解冻）

| 项 | 估算 | 依据 |
|---|---|---|
| 参数+梯度+AdamW | ~15GB | 总参数 ~1.05B：DINOv2 patch_embed ≈304M（`docs/repo_knowledge.md:121`）；aggregator 48 block × ~12.6M ≈ 605M（dim 1024、`aggregator.py:50-68`）；camera/DPT/GS/Part heads ≈150M。aggregator 常驻 bf16（`anysplat.py:124`）→ 605M×12B≈7.3GB；其余 ~450M fp32 master ×16B≈7.2GB |
| Transformer 激活 | ~2GB | 8×(32²+5)≈8.2K tokens。**gradient checkpointing 已硬编码开启**（`aggregator.py:71`、`vision_transformer.py:97-98`，均 `use_reentrant=False`），只存 block 边界：48×8.2K×2048×2B≈1.6GB + DINOv2 ≈0.4GB |
| DPT / GS head 激活 | ~3GB | features=256 多尺度融合，未 checkpoint，但有 `frames_chunk_size=8` 分块（`dpt_head.py:133`、`vggt_dpt_gs_head.py:41-66`） |
| 高斯 + 体素化 | ~1GB | 1.6M 逐像素 anchor 输入（`anysplat.py:307-354`），`voxel_size=0.002` 下 conf-softmax 加权融合，输出估 0.2–0.8M 高斯 ×84 维（训练日志有 `train/voxelize_ratio` 可实测校准，`anysplat_wrapper.py:142`） |
| 两路 gsplat 渲染 ×8 视角 | ~3–5GB | `decoder_splatting_cuda.py:78-86`；特征路（SH-deg0 + 8ch）比 RGB 路（SH4 = 48 系数）便宜 |
| **合计峰值** | **~28–32GB** | 余量 ~8–12GB |

### 每卡配置建议

- 1 场景 × 8 视角 @ 448 长边；bf16-mixed（各实验 yaml 已配）；梯度累积 1（现状）。
- **`max_img_per_gpu: 8`**（防 sampler 多塞场景，这是唯一的必改项）。
- 省显存开关清单：**无需新开**——checkpointing 已硬编码；无 GradScaler（bf16 不需要）；
  distill teacher 本就不在新配方里。
- OOM 时的砍序：① 视角上限 8→6（激活 ∝ 视角数）→ ② 分辨率 448→384 →
  ③ `voxel_size` 0.002→0.004（高斯数降）。checkpointing 已是底线，无可再开。

### 步耗时估计

VGGT-1B fwd+bwd @ 8×448²（含 ~33% checkpoint 重算）≈ 1.0–1.5s；加两路渲染 + loss ≈
**1.5–2.0 s/step** → 10k steps ≈ **4–6 小时**（单任务的量级，不含数据加载瓶颈）。

### 备注

- `config/experiment/instseg_anysplat.yaml:30` 的 `freeze_backbone: true` 是旧配方；
  新配方全解冻后 ~15GB 的参数/优化器状态是本次主要增量（冻结时此项 ≈ 新 head 的 ~2GB）。
- `voxelize: true, voxel_size: 0.002` 与各实验 yaml 现状一致（`instseg_anysplat.yaml:27-28`）。
