## Question

把数据管线对齐论文 4.1。这是本期**唯一**要碰数据管线的地方。三件事：

1. **视角数**：每次迭代随机采 **2–8 个 context view**。现在 `bounded_fixed` 是
   `num_context_views: 12` 固定。要么给它加随机化，要么新写一个 sampler
   ——**不要改 `bounded_fixed` 的既有行为**（其他 experiment 在用）。
2. **`num_target_views: 0`**：RGB 与实例监督都打在 context view 自身。依据：Eq.11 的
   $\frac{1}{N}\sum_{i=1}^{N}$ 上标就是输入视角数，Eq.3 的渲染也是用输入视角的位姿 $t_i$。
   pose-free 模型对 held-out 视角没有可信位姿，硬塞 target view 会引入论文没有的位姿误差。
   （想看泛化 PSNR 就在 validation 里单独做，val 可以用 GT 位姿。）
3. **分辨率**：长边固定 448，宽高比从 **五档离散** $\{0.5, 0.625, 0.75, 0.875, 1.0\}$
   随机采（即 $224/280/336/392 \times 448$）。

**第 3 条是有意偏离论文**，理由要写进 `## 解决`：论文是连续采样 $[0.5, 1.0]$，但那意味着
每步 tensor shape 都不同 —— cudnn autotune 缓存失效 + 显存分配器碎片化，在 A100 **40G**
上是实打实的 OOM 来源。离散五档保留了增广的鲁棒性收益（论文 Table 1 里 mIoU 对视角数
不敏感就来自这个增广），同时让显存按最大档预留一次即可。

要决策的：

- 五档是 **resize** 到目标宽高比，还是先 resize 再 **crop**？论文说 "resized such that the
  longer side is at most 448, the aspect ratio is randomly sampled" —— 读起来像是直接 resize
  （会改变物体长宽比），但现有 `crop_shim` 是裁剪路线。两者对实例边界的影响不同，选一个并说明。
- 视角数随机化后，同一 batch 内不同场景的视角数不同 → 是 padding 还是让 batch 内视角数一致？
  （倾向后者：同 batch 同视角数，避免 padding 污染 cross-view 项。）

**验证**（CPU）：采样器在 1000 次采样里视角数覆盖 2–8 且分布合理；五档 shape 各自出现；
`num_target_views: 0` 时下游不会去索引不存在的 target；既有 experiment 用
`bounded_fixed` 的行为逐位不变。
