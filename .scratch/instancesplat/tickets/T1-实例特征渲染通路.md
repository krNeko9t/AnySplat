## Question

把 `gaussian_instance_feat` 渲染回 2D，产出论文 Eq.3 的 $\tilde{S}_i \in \mathbb{R}^{H\times W\times 8}$。
**这是整条路线的地基**——现在实例特征已经挂在高斯上了却没人用，监督完全不经过 3D，
这正是与论文的核心差距。

已确认的事实（不用重查）：

- `src/model/arch/anysplat.py:534` 的 `voxelizaton_with_fusion(..., inst_feat=...)` **已经**
  做了论文 3.1 说的 confidence-aware 特征融合，产出 `gaussian_instance_feat [B, N_voxel, 8]`，
  与 `gaussians` 逐行对齐。这块不用写。
- `src/model/decoder/decoder_splatting_cuda.py` 用 `gsplat.rasterization`，
  `render_mode="RGB+D"`、`sh_degree=4`。gsplat 在 `sh_degree=None` 时把 `colors` 当**任意
  维度的原始特征**做 alpha 合成，正是我们要的。

要决策的：

1. **一次调用还是两次**：把 8 维特征拼进现有的 colors 张量（省一次光栅化，但 SH 与原始特征
   不能混，需要 `sh_degree=None` 且 RGB 退化成 0 阶）vs 单独一次 `rasterization` 调用
   （干净、但多一遍前向+反向的显存与时间）。**倾向两次调用**，理由是不动 RGB 路径 =
   不干涉既有实现，但要在票里给出显存代价的量化。
2. **背景色**：RGB 路径用 `background_color`（白）。特征路径的背景该填什么？
   0 向量？还是渲染出 alpha 之后只在 `alpha > 阈值` 的像素上算 loss？论文没说，
   但 Eq.4 有「valid pixel」的概念（$\Omega_k^{(i)}$ 是 valid 像素集），倾向后者。
3. **要不要除以 alpha**：alpha 合成出来的特征是 $\sum w_i f_i$，在 alpha < 1 的像素上
   模长会被压小，而 Eq.4 紧接着要做 $\ell_2$ 归一化——归一化会不会把这个问题自动消掉？
   （会，但零附近数值不稳。）决定是否需要 `/ (alpha + eps)`。

**契约要求**：新增字段走 `DecoderOutput` 上默认 `None` 的可选字段（照 `docs/layered_scheme.md`），
不改任何既有字段语义。`instance_feat_dim == 0` 时整条路径静默休眠。

**验证**（本机无 GPU，CPU 合成张量）：形状正确、梯度能从 $\tilde{S}$ 回到
`gaussian_instance_feat` 再回到 `PartHead`、`instance_feat_dim=0` 时与改动前逐位相同。
