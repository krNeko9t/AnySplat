## Question

不用改代码。

R2 的结论：re10k 的 id 是 IGGT 用 SAM2 track 造的，**构造上是全局的**（票里「逐帧独立」的
猜测已被证伪），但**残余漂移率无人量化**。两类失效后果完全不同：

- **碎裂**（同物体两 id）→ Eq.7 在该物体上变 no-op，**无害**。
- **漂移致 id 碰撞**（同 id 两物体）→ **会主动把不同物体的原型拉到一起**，比不做更糟。

要测的是**碰撞率**，不是碎裂率。

## 要做的

写一个一次性验证脚本（纯 numpy 读 `refined_ins_ids/*.npy` + rgb，**不需要深度、GPU、模型**），
三层判据：

1. **id × frame 占据矩阵** → 判「是不是全局」。决定性的一层。
2. **碎裂率**（参考量，解释第 3 层的分母）。
3. **碰撞率** ← **这才是要看的数**。对同一 id 在两帧之间算描述子距离：平均 RGB、
   实例面积、质心位移。碰撞表现为描述子的突变。

在 `scannetpp_v2` 上跑同一个脚本作**对照基线**——它是已知全局一致的，
它的碰撞率就是这套描述子判据的噪声底。没有这个基线，re10k 的数字读不出意思。

**前提**：先做完 T13。在路径 bug 和可能的错帧配对修好之前跑这个脚本，测到的「不一致」
分不清是上游标注问题还是我们自己的 bug。
