## Question

给训练期加三个**免聚类**的诊断标量，接进 `AnySplatWrapper.validation_step` 的 `self.log`。

这张票治的是 owner 的原始病症：「训出来效果不好，但说不清哪里不好」。loss 曲线在 0.x 震荡时，
无法区分**还没收敛**和**目标压根没在被优化**。这三个量把 loss 翻译成有物理含义的标量，
而且**恰好就是 $L_{pull}/L_{push}/L_{cross}$ 各自在优化的东西**，没有引入任何新超参：

1. `val/ins_intra`：GT 实例内，像素到本实例原型的平均距离（$L_{pull}$ 的裸量，去掉 margin 和
   hinge）。应该单调下降。
2. `val/ins_inter_min`：视角内实例原型两两距离的**最小值**（$L_{push}$ 的裸量）。应该上升，
   并且要盯住它有没有卡在某个上限——单位球面上两两分离是有容量上限的，实例一多就压不开，
   这本身就是重要信号。
3. `val/ins_cross`：同场景跨视角、同实例的原型距离（$L_{cross}$ 的裸量）。
   **这个量最能证伪**：如果它不降，要么 R2 的 id 对齐假设错了，要么渲染通路（T1）接错了。

再加两个塌缩探针：
- `val/ins_valid_ratio`：参与计算的有效像素占比（掉到很低说明 alpha 门槛或 valid mask 有问题）
- `val/ins_n_inst`：平均每视角的有效实例数（用来解释 `ins_inter_min` 的走势）

**口径必须与 loss 完全一致**，否则数字不可比：同样的 valid 像素判据、同样在 $\tilde{S}$
（渲染后）上算、同样先归一化再求原型。**直接复用 T2 里那个求原型的函数**，不要各写一份。

**注意**：`src/evaluation/instance_metrics.py` 是给 SegVGGT 的 query-mask 范式写的，
量不了 per-pixel embedding，**不要去改它**（那是别人的路线）。新写。

顺带把 validation 可视化扩成 `Context | GT inst | Pred inst(PCA) | Depth`：
渲染实例特征做 PCA 投影到 3 通道。注意 PCA 图与 GT 调色板互相独立，**看形状不看颜色**。

## R1 关闭后追加：一个免费的 step-0 断言

Eq.4 的原型是「先归一化再平均、**平均后不再归一化**」（`InstanceSplat.md:80`；对比语义分支
Eq.14 `:157` 有外层 `norm(·)`——论文里显式的不对称）。两个可直接用的推论：

1. **`‖f̄_k‖` 本身就是实例紧致度**，白送的第六个诊断量。原型落在单位球**内部**：
   实例内特征越一致，模长越接近 1；越发散，越接近 0。建议加 `val/ins_proto_norm`。
   它与 `val/ins_intra` 不冗余——intra 是绝对距离，模长是「方向一致性」，
   在特征整体塌缩时两者走向不同。

2. **健康的 step 0 是 pull/push/cross 三项全满值。** 初始化时所有原型模长≈0、挤在原点，
   所以三个 hinge 全部张开。→ **开局任何一项读数为 0，都是 bug 信号而不是收敛。**
   这是整张看板里最便宜、最早能发现「目标压根没在被优化」的判据，
   正好治本票开头说的那个原始病症。建议直接写成 smoke run 的一条断言，而不只是画在曲线上。
